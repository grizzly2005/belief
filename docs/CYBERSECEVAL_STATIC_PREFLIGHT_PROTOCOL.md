# CyberSecEval 4 Python static preflight protocol

Status: frozen before any BELIEF outcome was computed on the bound corpus.

This protocol adds a project-disjoint, public-input diagnostic to BELIEF. It is
deliberately narrower than the official CyberSecEval secure-code-generation
benchmark and narrower than an agent security benchmark.

## Eligibility decision

The public `instruct-v2.json` corpus is eligible for a **positive-only static
sensitivity preflight** because each record includes:

- a real open-source `origin_code` snippet;
- the line selected by Meta's Insecure Code Detector (ICD);
- a CWE identifier and detector pattern identifier;
- repository and source-path provenance.

It is not eligible for a primary comparative score because:

- it has no safe negative controls;
- its labels are ICD observations, not manually verified vulnerabilities;
- it has no executable functional or security oracle;
- the official metric evaluates code generated by an LLM, while this preflight
  analyzes the source snippets from which prompts were derived;
- Meta documents that ICD detects risky coding practices and can produce false
  positives.

Therefore this preflight cannot report precision, specificity, accuracy, false
positive rate, functional correctness, official CyberSecEval pass rate,
SecPass, or a Fable/Kimi leaderboard comparison.

## Frozen cohort

The upstream file contains 1,681 records. The runner selects every record whose
language is exactly `python`:

- 282 records;
- 279 repository identifiers;
- 281 unique `origin_code` strings;
- eight upstream CWE strata: CWE-78, CWE-89, CWE-94, CWE-312, CWE-328,
  CWE-338, CWE-502, and CWE-798.

Selection is fixed before BELIEF analysis and does not inspect BELIEF outcomes.
Repository paths are treated as opaque metadata and are never opened.

## Static classification

For each selected record, the runner:

1. locates every `origin_code` line whose trimmed text equals the upstream
   `line_text`;
2. parses `origin_code` with Python's AST parser without importing it;
3. applies only BELIEF's fixed default security-pattern and taint analyzers;
4. projects upstream CWEs through the preregistered semantic equivalence map;
5. requires a mapped finding anchor to intersect an upstream target line.

The possible classifications are:

- `detected`: a mapped BELIEF CWE finding is target-line aligned;
- `missed`: the snippet is evaluable but no mapped target-line finding exists;
- `abstain`: Python parsing failed, the target line could not be located, or an
  analyzer raised an exception.

Abstentions count as misses in the conservative lower-bound sensitivity.
No source, prompt, target-line text, external input path, or analyzer evidence
text is retained in a result. Per-case results retain only identifiers,
digests, counts, CWE, classification, and sanitized finding coordinates.

## Preregistered metrics and gates

The report includes:

- AST parseability and target-line-location rates;
- evaluability and abstention rates;
- target-pattern sensitivity with abstentions in the denominator;
- target-pattern sensitivity on evaluable cases;
- the same diagnostics for BELIEF's declared CWE overlap and per upstream CWE;
- two same-checkout deterministic repetitions.

The engineering gates were frozen before the first run:

| Gate | Threshold |
|---|---:|
| AST parseability | at least 0.85 |
| Abstention | at most 0.15 |
| Analysis exception rate | exactly 0 |
| All-case sensitivity lower bound | at least 0.50 |
| Evaluable-case sensitivity | at least 0.60 |
| Declared-overlap sensitivity lower bound | at least 0.55 |
| Same-platform repetition stability | exactly 1.00 |

Passing these gates would establish only that this adapter and static analyzer
cover a useful fraction of public ICD-derived Python patterns. It would not
establish vulnerability accuracy or benchmark leadership.

## Safety and authorization

The runner requires the explicit
`--acknowledge-external-public-code` flag. Its authorization is limited to
reading the exact bound JSON and parsing its source strings in memory.

The runner never:

- imports an external module;
- accepts a module or callable;
- executes source text;
- invokes a model;
- uses network, subprocess, shell, or Docker;
- opens the SusVibes holdout or BELIEF's reserved web corpus;
- overwrites an existing result.

Example, after obtaining the exact upstream dataset independently:

```powershell
python scripts/run_cyberseceval_static_preflight.py `
  --dataset C:\path\to\instruct-v2.json `
  --output benchmark_cyberseceval_results\python-instruct-v2-static-v1.json `
  --belief-revision <full-lowercase-git-sha> `
  --acknowledge-external-public-code
```

The authoritative machine-readable protocol is
`benchmark_cyberseceval/preregistration.json`.
